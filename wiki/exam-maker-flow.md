# Exam Maker & Participant Lifecycle

The Maker-Participant flow is the core collaborative feature of StuDay. It allows instructors or creators to compose tests and participants to join instantly using a short code without account creation.

---

## 1. End-to-End Workflow Diagram

```text
[Maker / Creator]
       │
       ▼
 1. ExamMakerScreen
       ├── Set Title, Subject & Description
       ├── Configure Timer (durationMinutes) & Item Limits (questionLimit)
       ├── Add Questions manually OR Bulk Import (BulkQuestionParser)
       ├── Reorder Sections: [MCQ, True/False, Matching]
       └── Tap "Publish"
               │
               ├── Generates 6-char Code: e.g. "4F9K2Q"
               ├── Saves to Supabase (public.exams)
               └── Backs up locally (quizz_created_exams_v2)
                       │
                       ▼
            Share Code "4F9K2Q" with Learners
                       │
[Participant / Learner] 
       │
       ▼
 2. ExamJoinScreen
       ├── Enter Code "4F9K2Q" + Nickname
       └── Tap "Join Exam"
               │
               ▼
 3. ExamPlayScreen
       ├── View questions grouped by Section Order
       ├── Answer MCQ, True/False, and Connect Matching Pairs
       ├── Pacing: Self-paced with countdown timer (if configured)
       └── Tap "Submit Exam" (or auto-submit on timeout)
               │
               ▼
 4. ExamParticipantResultScreen
       ├── View Score & Percentage
       └── Review Questions & Explanations (subject to ShowAnswersMode)
               │
               ▼
 5. ExamDashboardScreen (For Maker)
       └── Live real-time participant roster, average score, and metrics
```

## 2. 6-Character Join Code System

- Generated by `CodeGenerator.generateCode(length: 6)`.
- Uses unambiguous uppercase alphanumeric characters (excluding confusing characters like `0`, `O`, `1`, `I`):
  `'ABCDEFGHJKLMNPQRSTUVWXYZ23456789'`.
- Guaranteed uniqueness via PostgreSQL `UNIQUE` constraint on `exams.code`.

## 3. Supported Question Types & Data Shapes

### A. Multiple Choice (`QuestionType.multipleChoice`)
- Exactly 1 prompt (`questionText`).
- 2 to 6 options (`choices`).
- At least 1 choice marked `isCorrect: true`.

### B. True / False (`QuestionType.trueFalse`)
- Exactly 1 prompt.
- 2 predefined choices: "True" and "False".
- Explanations (`explanation`) are strongly recommended to provide learning value.

### C. Matching Type (`QuestionType.matching`)
- Exactly 1 prompt or instructions (e.g. "Match the terms with their definitions").
- 2 to 10 pairs (`matchingPairs`):
  - `leftText`: Premise / Term.
  - `rightText`: Definition / Target match.
- During play: The right column items are shuffled to prevent positional bias.

## 4. Bulk Question Parser (`lib/core/utils/bulk_question_parser.dart`)

Makers can paste hundreds of raw questions at once via `BulkImportQuestionsDialog`. The parser supports:
1. **Numbered questions**: `1. What is...`, `2) What is...`, `Q1: What is...`
2. **Choice formats**: `A. ...`, `B) ...`, `a. ...`
3. **Answer keys**: `Answer: A`, `Ans: True`, `Correct: B`
4. **Matching syntax**: `Premise -> Match` or `Term = Definition`
5. **Inline explanations**: `Explanation: ...` or `Ref: ...`

---

## 5. Grading and Scoring Logic

Grading runs client-side in `ExamParticipantController.submitExam()` and is verified in the backend:
- **Multiple Choice**: Correct if selected choice has `isCorrect == true`. Awarded `question.points`.
- **True / False**: Correct if selected boolean option matches the designated correct choice.
- **Matching Type**: All pairs must match correctly to earn full points, or graded proportionally depending on section settings.
- Results are saved into `ExamResponse` records and recorded in `exam_participant_answers`.
